1

Create User Account

bash
sudo adduser dineesh

PURPOSE/EXPLANATION

Creates a new system user account named "dineesh" that will be used for email authentication. Mail servers use Linux system accounts for user authentication.

WHAT TO DOCUMENT

  • The command entered
  • Password prompts appearing
  • Full name and user info prompts
bash
sudo passwd dineesh

PURPOSE/EXPLANATION

Sets the password "Lab2026" for the dineesh user account. This password will be used later for SMTP/IMAP authentication when connecting with email clients.

WHAT TO DOCUMENT

  • Password prompt
  • Success confirmation message
2

Set Hostname

sudo hostnamectl set-hostname bnaserver.bungkus.org

PURPOSE/EXPLANATION

Sets the Fully Qualified Domain Name (FQDN) of the server. This is critical because:

  • Mail servers identify themselves using FQDN
  • SSL certificates are issued to the FQDN
  • Other mail servers use this for routing
hostnamectl

PURPOSE/EXPLANATION

Verifies the hostname was set correctly. This displays system information including the static hostname, which should now be "bnaserver.bungkus.org".

WHAT TO DOCUMENT

  • Static hostname field showing bnaserver.bungkus.org
  • Operating system information
  • Kernel version
hostname -f

PURPOSE/EXPLANATION

Displays only the FQDN (Fully Qualified Domain Name). This is a quick way to verify the hostname is correct before proceeding.

Expected Output: bnaserver.bungkus.org
3

Configure Hosts File

sudo nano /etc/hosts

PURPOSE/EXPLANATION

Opens the hosts file for editing. This file maps IP addresses to hostnames locally, allowing the server to resolve its own hostname without DNS.

Add This Line

192.168.200.3 bnaserver.bungkus.org bnaserver

EXPLANATION OF ENTRY

  • "When you see bnaserver.bungkus.org or bnaserver, use IP 192.168.200.3"
  • This is essential for the mail server to identify itself correctly

WHAT TO DOCUMENT

  • The complete /etc/hosts file with your addition
  • Highlight the line you added
Verify Save
cat /etc/hosts

PURPOSE/EXPLANATION

Displays the contents of the hosts file to verify your changes were saved correctly.

WHAT TO DOCUMENT

  • Verify the line you added is present

Network Verification

ip addr show

PURPOSE/EXPLANATION

Displays all network interfaces and their IP addresses. Use this to verify your server has the correct IP (192.168.200.3) assigned.

WHAT TO DOCUMENT

  • Interface name (usually enp0s3)
  • IP address 192.168.200.3
  • Netmask and broadcast
ip route

PURPOSE/EXPLANATION

Shows the routing table, including the default gateway. Critical check as hostname changes can sometimes remove the gateway!

WHAT TO DOCUMENT

  • Default route (check if you have "default via 192.168.200.X")
  • Local network route

🚨 IMPORTANT GATEWAY NOTE

If you don't see ANY "default via" line, you need to add one!

sudo ip route add default via 192.168.200.1 dev enp0s3
ping -c 3 8.8.8.8

PURPOSE/EXPLANATION

Tests internet connectivity by pinging Google's DNS server.

⚠️ VirtualBox NAT Limitation

If ping fails with "Network unreachable", this is NORMAL! VirtualBox NAT blocks ICMP packets. In documentation, explain this and use curl instead.

curl -I https://google.com

PURPOSE/EXPLANATION

Tests HTTP/HTTPS connectivity by fetching headers from Google. More reliable than ping in VirtualBox.

WHAT TO DOCUMENT

  • HTTP status code (301 or 302)
  • Confirms working internet

Phase 2: SSL/TLS Certificate Generation

6

Generate Self-Signed Certificate

sudo openssl req -new -x509 -days 365 -nodes \
  -out /etc/pki/tls/certs/bnaserver.pem \
  -keyout /etc/pki/tls/private/bnaserver.key \
  -subj "/C=MY/ST=KL/L=APU/O=SNA/CN=bnaserver.bungkus.org"

PURPOSE/EXPLANATION

Generates a self-signed SSL/TLS certificate (valid 365 days). Broken down:

  • -nodes: No passphrase for automated service start.
  • CN=bnaserver.bungkus.org: Critical hostname match.
Verify Files
sudo ls -l /etc/pki/tls/certs/bnaserver.pem
sudo ls -l /etc/pki/tls/private/bnaserver.key
7

Permissions & Details

sudo chmod 600 /etc/pki/tls/private/bnaserver.key
sudo chmod 644 /etc/pki/tls/certs/bnaserver.pem

PURPOSE/EXPLANATION

Secures the private key (600 - root only) and makes the cert public (644). Only root should ever touch the private key.

Human-Readable Inspection
sudo openssl x509 -in /etc/pki/tls/certs/bnaserver.pem -text -noout

WHAT TO DOCUMENT

  • Subject showing CN=bnaserver.bungkus.org
  • Validity dates and Issuer info

Critical Troubleshooting Logs

Initial Hurdles

PROBLEM 1: "Failed to Find Settings" Error

Thunderbird couldn't auto-detect the server settings automatically and displayed a warning banner during the account creation phase.

Resolution

This occurs when SRV/DNS records aren't set up. The manual configuration performed in Phase 10 bypasses this by explicitly defining ports and protocols.

Issue Identified

PROBLEM 2: "No Information Available" Certificate Hang

When trying to add a security exception, Thunderbird displayed "Unable to obtain identification status for this site" and hung indefinitely.

ROOT CAUSE

Thunderbird attempts to validate our self-signed certificate using OCSP (Online Certificate Status Protocol). This requires internet access to a Certificate Authority (CA) that doesn't exist for our local lab environment, causing the client to wait indefinitely for a response that never comes.

🛠️ THE FIX: Disable OCSP Validation

  1. Go to Settings in Thunderbird.
  2. Search for "OCSP" in the search bar.
  3. UNCHECK the box: "Query OCSP responder servers to confirm the current validity of certificates".
Performance Issue

PROBLEM 3: "Checking Password" Infinite Loop

Even after attempting to bypass the certificate screen, Thunderbird got stuck on a "Checking password..." spinner for an extended period.

❌ FAILED ATTEMPT

Attempting to use the "Add Exception" dialog with the location https://bnaserver.bungkus.org:993 failed because the https:// protocol is incorrect for a mail server connection, leading back to the "No Information Available" hang.

🚀 THE FIX: Use IP Address for Direct Connectivity

Change both the Incoming and Outgoing server hostnames to the literal IP address: 192.168.200.3.

Why? This forces a direct connection and bypasses local DNS or hostname resolution delays/errors that contribute to the infinite checking loop.

SUCCESS: FINAL VICTORY

After applying the OCSP and IP-connectivity fixes, Thunderbird successfully recognizes the local certificate, validates credentials instantly, and grants access to the Inbox.

Mission Accomplished: Fully encrypted local mail delivery.
